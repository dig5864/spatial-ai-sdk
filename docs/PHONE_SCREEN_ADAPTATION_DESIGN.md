# 固定支架与反射镜片下的多手机屏幕适配方案

日期：2026-10-13。本文记录设计分析。Android 参数读取、物理布局、校正保存、配置导出及整体原生提交已实现，具体范围见 [使用与验证](PHONE_SCREEN_ADAPTATION.md)；每眼独立投影等完整光学扩展仍属后续规划。

初始分析基于 SDK 提交 `23484ed` 及工作区源码。当前小米 AA 区已核对像素布局，但屏幕物理尺寸和完整光学标定仍待测量，见 [小米光学验收记录](XIAOMI_OPTICS_SCALE_VALIDATION.md)。下文的“现有行为”表描述改造前基线。

## 1. 实现结论

可以支持不同手机。建议将方案实现为：**固定支架光学配置 + 手机有效屏幕物理尺寸 + 屏幕安装定位 + 当前输出分辨率 → 左右眼像素区域 → 原生双目显示**。

读取屏幕参数后分屏的方向正确，但不能仅按分辨率等分屏幕，也不能直接按新旧分辨率比例缩放小米矩形。镜片固定时，要求保持的是光路对应的屏幕上的物理位置和物理尺寸；像素数随手机和当前显示模式变化。

例如，同样输出 2400×1080 的两台手机，有效屏幕宽度分别为 144 mm 和 160 mm，则 40 mm 宽的显示区分别约占 667 和 600 像素。直接沿用同一像素矩形，会改变真实显示尺寸。这组尺寸只是计算示例，不代表当前小米实测值。

推荐先完成 Android 的自动布局：已知手机读取配置，未知手机读取系统参数并提供一次性物理尺寸/定位校正，之后缓存。支架、镜片和固定 UVC 使用同一套硬件配置，手机不再各自保存一套光学像素矩形。

## 2. 固定与变化的参数

| 参数 | 归属 | 换手机后的处理 |
| --- | --- | --- |
| 镜片结构、反射方向、畸变、屏幕设计平面 | 支架光学配置 | 在几何条件相同时复用 |
| 每眼有效区和光学中心，单位 mm | 支架光学配置 | 转换到新手机像素，不重新按屏幕一半推导 |
| 标定所用眼位、双眼投影、设计瞳距 | 支架光学配置/佩戴设置 | 手机变化本身不改变；眼位/瞳距调整另行处理 |
| UVC 相机内参及相机到支架/物理头部的外参 | 相机与支架配置 | 同一相机、采集模式和安装条件下复用 |
| 有效发光区域宽高、屏幕边缘到夹持基准的距离 | 手机屏幕配置 | 读取已验证数据或测量 |
| 当前显示模式、输出 Surface 尺寸、窗口偏移和方向 | 运行时参数 | 自动读取并随变化重建 |
| 手机屏幕相对支架的安装位置 | 安装配置 | 由机械定位保证或逐机校正 |
| 手机 IMU 坐标和安装映射、性能、USB 兼容性 | 主机配置/运行时能力 | 单独适配，不由屏幕分屏推导 |

“支架固定”不自动意味着“换手机后屏幕平面和原点固定”。不同手机的边框、厚度、外壳和保护套会影响定位：夹持机身中心不等于夹持有效屏幕中心，靠背定位也可能让屏幕到镜片的距离变化。

第一版应明确机械约束：屏幕朝向与倾角一致、屏幕发光平面位于同一设计平面、安装平移可确定。若这些条件已经由支架保证，换手机的显示适配可以主要归结为屏幕尺寸和分辨率换算；否则还需要安装偏移，甚至重新求投影和畸变。屏幕参数接口无法测出这些机械量。

## 4. 如何读取屏幕参数

### 4.1 必须区分的四种尺寸

1. **屏幕有效物理尺寸**：有效发光区域宽高，单位 mm，不含机身边框。
2. **显示模式像素尺寸**：Android 当前 Display Mode 的尺寸。
3. **窗口与最终输出 Surface**：应用占据屏幕的哪个区域、最终帧缓冲宽高；它们可能与显示模式尺寸不同。
4. **每眼 RenderTexture**：渲染质量参数，可以降低以提升帧率，不应改变最终 AA 区的物理尺寸。

Android `Display.Mode.getPhysicalWidth/Height()` 返回该模式的像素尺寸，不是毫米尺寸；应用可能使用不同尺寸的缓冲区再经系统缩放。因此必须分别采集显示模式与应用输出。依据：[Android Display.Mode](https://developer.android.com/reference/android/view/Display.Mode)。

### 4.2 Android 采集建议

新增平台适配组件 `AndroidScreenMetricsProvider`（拟新增），通过 Unity JNI 或 Android 插件读取 Activity 所在显示器的信息，返回一个版本化快照：

| 字段 | 建议来源 | 用途 |
| --- | --- | --- |
| 厂商、型号、deviceCode | 已有 `ReadHostIdentity()` | 查找已验证手机尺寸配置 |
| displayId、rotation、modeId、模式宽高/刷新率 | Activity 对应 Display / Display.Mode | 判断显示目标、方向与模式变化 |
| 窗口 bounds、system bars/cutout insets | API 30+ 的 WindowMetrics / WindowInsets | 确认窗口边界与不可用区域 |
| 最终 Surface/帧缓冲宽高和输出 viewport | Android Surface 与原生显示 Provider；对照 Unity `Screen.width/height` | 最终像素换算和提交契约 |
| xdpi、ydpi、与之配对的尺寸/方向信息 | DisplayMetrics | 推算物理尺寸的候选值 |
| Unity `Screen.safeArea` | Unity | 诊断对照，不自动作为光学整体平移 |

API 28–29 使用带版本分支的 Display metrics 与窗口/Surface 回调实现同一快照契约；旧 API 返回值仍需与实际输出核对。WindowMetrics 包含系统栏区域，不能把它的宽高直接当成最终全屏 Surface 尺寸。依据：[Android WindowMetrics](https://developer.android.com/reference/android/view/WindowMetrics)。

横竖方向统一到当前实际横屏坐标，记录转换，不仅对宽高做 `max/min`；DPI 轴、窗口偏移、刘海区域和安装定位也必须经过同一次方向转换。显示模式本身的轴约定需与实际 rotation 核对。

### 4.3 物理尺寸的来源优先级

1. 用户保存的实测尺寸/尺子校正结果，绑定手机和配置版本。
2. SDK 中该型号经过验证的有效屏幕尺寸数据。
3. 系统 `xdpi/ydpi` 的估算，经一致性检查后用于开发预览。
4. 已知有效屏幕对角线和有效长宽比的估算，仍标记为估算；没有可靠输入时提示填写有效宽高或执行尺子校正。

Android 将 `xdpi/ydpi` 定义为各轴物理 PPI，`densityDpi/density` 用于 UI 缩放，不能代替物理测量。依据：[Android DisplayMetrics](https://developer.android.com/reference/android/util/DisplayMetrics)。Unity 的 Android `Screen.dpi` 使用逻辑 `densityDpi`，且官方提示部分设备的 `xdpi/ydpi` 也可能上报错误，因此不能直接用 `Screen.dpi` 计算准确 mm。依据：[Unity Screen.dpi](https://docs.unity3d.com/ScriptReference/Screen-dpi.html)。

仅在像素尺寸和 DPI 属于同一坐标尺度、同一轴时，可采用：

```text
physicalWidthMm  = metricsWidthPx  / xdpi * 25.4
physicalHeightMm = metricsHeightPx / ydpi * 25.4
```

不可将原生模式宽度与逻辑窗口 DPI 任意拼接。估算结果应核对有效宽高比、横纵像素尺度、模式切换前后的物理尺寸一致性，并用屏幕标尺实测。对角线法只适用于明确的有效区域：圆角、曲面与标称尺寸可能引入偏差；首版优先支持平面有效区域。

尺子校正应在已知全屏映射下分别显示横、纵线段，用户调整至指定实测长度，例如 50 mm，反推当前输出 px/mm。保存推导出的物理宽高及测量时的模式/Surface 信息，下次分辨率变化后重新计算像素尺度，不能永久复用旧 px/mm。

## 5. 分屏计算模型

### 5.1 坐标与输入

在支架的设计屏幕平面建立二维坐标：X 向右、Y 向下，单位 mm。左右眼区域 `R_L/R_R` 和每眼光学中心 `O_L/O_R` 均保存于该平面。两个区域可不对称，不要求铺满手机。

第一版限定手机屏幕与该平面重合且轴对齐。手机有效屏幕左上角在支架坐标中为 `(sx,sy)`，有效宽高为 `Wmm/Hmm`。屏幕中心定位、机身边缘定位分别使用不同的安装规则计算 `(sx,sy)`；靠机身边缘定位还需屏幕到机身边缘的距离。

设最终完整屏幕输出为 `Wpx/Hpx`，则：

```text
kx = Wpx / Wmm           // 输出 px/mm
ky = Hpx / Hmm

对每眼支架矩形 (xmm, ymm, wmm, hmm)：
xpx = (xmm - sx) * kx
ypx = (ymm - sy) * ky
wpx = wmm * kx
hpx = hmm * ky

光学中心：opx = (oxmm - sx) * kx，opy = (oymm - sy) * ky
```

若支架以有效屏幕中心 `(ax,ay)` 定位，则 `sx=ax-Wmm/2`、`sy=ay-Hmm/2`。若靠左/底边定位，应按相应基准求偏移，不套用屏幕居中规则。

计算保留浮点边界；网格用浮点位置，光栅裁切在最后统一取整，避免多次取整造成不同眼不一致。支架上的物理方形不一定对应像素方形，必须使用各轴尺度；异常横纵比例先检查参数和输出映射。

### 5.2 非全屏与坐标转换

首版要求真正全屏、固定 `LandscapeLeft`，并核对 C# 尺寸与原生输出，尽量建立“完整屏幕坐标 → 最终 Surface 坐标”的单一映射。

如果应用窗口只覆盖部分屏幕，需先得到完整屏幕上的 AA，再减去窗口在完整屏幕中的偏移，并按 Surface 与窗口之间的比例转换。不能把完整屏幕的 mm 直接除以局部窗口宽度。首版遇到无法确认映射的分屏窗口、兼容模式黑边或外接显示，返回明确的布局不可用状态。

内部统一采用左上角原点。最终 OpenGL scissor 若采用左下角原点，转换 `yBottom=Hpx-(yTop+h)`；不能在 C# 和原生两次转换。反射、180° 输出和左右眼身份单独定义，不根据分辨率重新猜测。

### 5.3 可用范围校验

- 两眼区域均在有效发光区域内，互不重叠，并满足指定光学中心/设计视场的覆盖要求。
- 检查刘海、挖孔、圆角、曲面边缘与系统遮挡是否侵入区域；不可仅依据外接矩形判断所有像素可见。
- 检查原生输出尺寸、方向和配置版本一致，所有数值有限且尺度为正。
- 现有原生接口要求左眼位于左半屏、右眼位于右半屏；首版先将此限制作为支持条件。如果支架偏置导致合理区域跨越半屏，应扩展原生校验，而非平移区域来迎合接口。

屏幕过小或被遮挡时，不能自动缩小整个双眼内容来塞进去，这会改变物理尺度和融合条件。默认提示调整安装或手机不满足全视场要求；若后续提供缩小视场模式，需同步更新投影、网格采样/裁切及验证范围。

## 6. 光学、UVC 与 IMU 如何复用

### 6.1 光学网格和投影

当手机发光平面、镜片、眼位以及物理有效区不变时，可复用同一支架标定，并把显示网格的物理位置映射到新像素。更大的屏幕通常只是黑边变多；更高的分辨率提高采样精细度，不应自动增大视场或场景物体。

前提是网格和投影已经针对这套支架完成标定。当前 RhinoX 参考网格与历史视锥不能仅因支架固定就视为适用。建议建立独立 `RigOpticsProfile`，保存每眼物理区域、独立光学中心、投影、方向、网格身份与适用屏幕平面；网格几何保存物理坐标，或规范化到固定的物理区域，并明确两者换算。

每眼 AA 是输出范围，投影负责空间尺度，畸变网格负责光线映射；三者共同形成标定，单独调整 viewport 不足以纠正 FOV 或物理尺度。手机安装 Z 距离/倾角超出标定范围时，应重新建立对应的光学配置，而非只修改 AA 偏移。

当前光学描述及原生入口传入一套公共视锥；如果固定支架实测需要不同的左右眼视锥，应扩展为 per-eye 参数，不由 AA 中心反推共用投影。光学中心也应参与网格/投影模型，而非仅保存为诊断字段。

### 6.2 UVC 固定在支架上

同一 UVC 的内参随其成像模式、裁切、图像缩放或对焦状态变化，而不随手机屏幕分辨率变化；相机到固定支架/物理头部的外参在安装和佩戴基准不变时可复用。换手机后无需因为屏幕不同而重新标定 UVC，但仍检查设备身份、协商图像模式、镜像/旋转和 USB 能力。

手部三维位置继续从 UVC 图像和相机标定计算，进入物理头部/追踪坐标，再由新的显示布局渲染。禁止按手机分辨率比例缩放三维手骨架。`headFromCamera` 的基准必须明确，不能绑定到每台手机的 IMU 原点。

当前 `cameraSource`、`reflectHandDisplayX`、`uvcSwapHandedness` 部分位于手机 Profile。应分别拆分为支架设备来源、显示光路补偿、相机输入/手别约定；迁移时保留现有优先级，避免重复镜像。相机标定已有独立工具与状态，见 [UVC 阶段 2](UNITY_XR_HANDS_STAGE2.md)。

### 6.3 手机 IMU

换手机还会换 IMU 及其安装位置。屏幕适配成功不能证明追踪适配成功。固定屏幕朝向和安装倾角可复用支架的安装旋转，但传感器坐标仍需经过已有 Cardboard 转换并核验。IMU 到眼位的杆臂若依赖手机硬件位置，则需独立处理，不能盲目复用某机型的外参。

当前只支持 3DoF，这一能力边界保持不变。布局、光学、IMU、相机标定各自报告状态，不用一个手机验证标记覆盖所有能力。

## 7. 建议的 SDK 模块与数据契约

以下均为拟新增，字段最终命名在实现时确定：

| 模块/数据 | 主要职责与字段 |
| --- | --- |
| `ScreenMetricsProvider` | 读取模式、窗口、输出 Surface、方向、DPI、遮挡，生成不可变快照和 revision |
| `PhoneScreenProfile` | 型号匹配、有效宽高 mm、尺寸来源、测量记录与版本；不保存每眼固定像素矩形 |
| `ScreenMountProfile` | 支架定位规则、屏幕到夹持基准的偏移、屏幕平面/倾角、测量版本 |
| `RigOpticsProfile` | rigId、设计屏幕平面、每眼区域/光学中心 mm、双眼投影、网格与反射方向、光学验证范围 |
| `StereoLayoutCalculator` | Core 纯数学计算，输入配置与快照，输出完整屏幕/Surface 的两眼区域及兼容性结果 |
| `ResolvedDisplayConfiguration` | 布局 revision、目标 Surface 尺寸、两眼区域/投影、网格身份、方向和质量状态 |
| `SpatialCardboardBridge` | 协调读取、解析、计算与原生提交；检测提交接受和实际应用，公开结果 |

建议结果状态分为 `ReadyMeasured`、`ReadyEstimated`、`NeedsScreenMeasurement`、`NeedsMountAlignment`、`UnsupportedGeometry`、`OutputMappingMismatch`。前两项只说明布局输入的可靠程度，额外提供 `opticsValidated` 等状态；`ReadyMeasured` 不自动代表完整光学验收通过。

支架没有电子设备 ID 时，可由应用配置/设置选择 `rigId`；不能用手机型号或 USB 相机 VID/PID 自动代替光学支架身份。同一 UVC 型号可能安装在不同支架中。

### 7.1 初始化与恢复

```text
选择固定支架配置
    ↓
设置全屏与 LandscapeLeft，等待输出 Surface 有效且方向稳定
    ↓
读取屏幕快照 → 解析物理尺寸 → 解析安装定位
    ↓
计算两眼区域 → 校验可见范围与输出映射
    ↓
提交完整原生配置 → 确认原生已应用同一 revision
    ↓
开始双目显示，并公开布局/光学/相机/追踪状态
```

显示模式、Surface、方向或安装配置变化，及应用恢复前台时，重新取得快照；值相同则不重建。生成新配置后在帧边界整体切换，失败不显示“新屏幕尺寸 + 旧 AA”的混合结果。尺寸尚未就绪时保持等待，暂时保留竖屏或 0 尺寸不能永久判定不支持。

### 7.2 原生接口策略

短期可复用 `ConfigureSpatialEyeRects()` 进行诊断原型，但现有“光学配置 + 矩形”分两次提交会产生中间状态，运行时模式切换还缺少完整确认。

正式实现建议提供带版本的整体显示配置入口：一次提交 Surface 尺寸、两眼 AA、方向、网格和 per-eye 投影，在原生渲染线程安全应用，并返回/查询已应用 revision。保留现有 RhinoX 原生面板路径与旧诊断入口，避免改变一体机的分辨率校验。

## 8. 分阶段实施

| 阶段 | 工作 | 交付/完成条件 |
| --- | --- | --- |
| 0：建立固定基准 | 测量当前小米有效屏幕宽高和安装定位；确认设计屏幕平面；采集两眼中心/有效范围；区分像素布局基准与光学标定 | 可追溯的支架与参考手机参数，不把估计值写成实测 |
| 1：屏幕参数服务 | 实现 Android 版本分支、Unity/原生尺寸对照、物理尺寸优先级、未知手机校正与缓存 | 可输出完整快照，切换分辨率后毫米尺寸保持一致 |
| 2：物理布局计算 | 新增 Core 计算器，生成动态 AA；接入桥接；保留旧小米与 RhinoX 路径 | 原基准条件复现现有矩形；不同手机/模式保持物理位置与尺寸 |
| 3：配置分离与原生提交 | 支架共用光学/UVC 选择迁出 Host；正式网格/投影配置与原子更新 | 未知手机不依赖型号白名单即可使用固定 UVC；无配置中间帧 |
| 4：实机验收 | 至少两种有效物理尺寸、两档分辨率；裸屏测量和镜片后对比；重插手机、暂停恢复与 UVC 回归 | 兼容矩阵、量化误差和测量证据，按范围更新验证状态 |

实施优先级：先取得可信物理尺寸和机械定位，再实现自动 AA；沿用光学候选参数时明确记录候选状态，随后完成这套固定支架的光学验收。不需要首先为每款手机手工编写独立像素区域。

## 9. 验证与验收

### 9.1 数学与生命周期验证

以下是后续实现需要覆盖的场景，本文未执行这些测试：

| 场景 | 预期 |
| --- | --- |
| 同一手机，输出像素宽高减半，物理尺寸不变 | AA 像素位置/宽高随输出映射变化，屏幕上的 mm 位置/尺寸不变 |
| 相同分辨率、不同物理屏幕尺寸 | 按各自 px/mm 计算，不生成相同像素区域 |
| 屏幕中心定位与机身边缘定位 | 分别得到正确的原点偏移；不默认两者相同 |
| 横纵 DPI 不同、竖横屏切换 | 成套转换尺寸、坐标和 DPI 轴；错误方向下等待或停止显示 |
| 缺失/错误 DPI、型号未知 | 提供测量/校正路径，不猜测为已验证小米 |
| AA 越界、两眼重叠、跨越原生半屏限制或遮挡 | 明确报告原因，不静默夹紧或缩放 |
| 降低每眼 RenderTexture 分辨率 | 清晰度变化，最终 AA 与物理尺寸不变 |
| 模式切换、暂停恢复、Surface 重建、原生配置失败 | revision 一致，无陈旧或部分配置生效 |

### 9.2 实机测量

先在裸屏上检查每眼矩形边界、中心十字和指定长度标尺，用尺子核对真实 mm 尺寸与支架基准位置。截图只检查输出像素，不能证明物理尺寸正确。

再通过镜片分别检查左右眼及双眼：单眼中心和边缘形状、真实标靶尺度、融合/上下错位、深度和动态响应。重复取放手机，验证机械定位可重复；同时验证 UVC 相机空间结果没有被手机显示尺寸变化缩放。

建议开发阶段先将裸屏标尺及定位误差 **≤1 mm** 作为候选目标，正式容差需根据机械精度和光学敏感度确定。光学尺度、双眼融合、动态误差应沿用 [光学验收流程](XIAOMI_OPTICS_SCALE_VALIDATION.md) 事先约定量化标准；本方案没有现成实测通过数据。

每次保存手机身份、系统版本、rigId、有效物理尺寸来源、安装参数、模式/Surface/方向、计算出的 AA、光学和相机版本、实测误差。兼容矩阵区分“布局可计算”“机械可安装”“光学已验证”“UVC 可运行”和“性能通过”。

## 10. 实现前所需输入
 
- 当前参考手机有效发光区域的实际宽高 mm，不能只提供屏幕分辨率或机身尺寸。
- 支架对手机的定位基准：有效屏幕中心、机身中心还是某条边；是否使用保护套。
- 不同手机是否能保持发光平面和倾角一致，以及可支持的宽高/厚度范围。
- 固定光学模组的每眼有效物理区域、光学中心、眼位、网格/投影及验证范围。
- 固定 UVC 的设备/实例标识、实际采集模式与现有相机标定版本。

在这些数据齐备后，SDK 可以将换手机流程变成“自动识别参数 → 必要时一次性尺寸/定位校正 → 自动计算分屏”，复用同一支架和 UVC 配置。
