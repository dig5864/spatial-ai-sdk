## 目标与当前基线

目标是让用户导入 Spatial AI SDK 后，使用 Unity 标准 XR Hands 获取左右手数据，
并通过 XR Interaction Toolkit（XRI）开发手部交互。手机双目显示与头部 3DoF 继续使用现有 Cardboard XR 链路。
无需为了手部接入先实现完整 OpenXR runtime。

当前已有：小米 2206123SC、HXQ UVC 640×480@30、手动曝光控制、MediaPipe VIDEO 双手识别（默认 CPU，GPU 可配置），
以及 SDK 自有 `SpatialHandTracking` 接口。用户有手采样约 22～24 FPS。
配套包已提供独立的模拟和真实 UVC XR Hands Provider，手机 `xrhands` 场景消费标准 `XRHandSubsystem`。
目前数据主要是图像中的 21 个关键点，不是已标定的米制关节姿态。
详见 [UVC 与手势进展](UVC_HAND_TRACKING_PROGRESS.md)。

预期链路：

```text
模拟三维手 / UVC + MediaPipe
          ↓
统一手部帧：时间、左右手、关节姿态、有效性、估算来源
          ↓
Spatial AI XR Hands Provider → XRHandSubsystem
          ↓
Unity 手部可视化 / 手势检测 / XRI 输入与交互
```

先验证标准接口，再接真实空间数据；不将模拟验收、单目估算或帧率提升等同于空间交互验收。

## 阶段概览

| 阶段 | 实现重点 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0 | 依赖、坐标与能力契约 | 兼容矩阵、数据契约、验收场景清单 | 边界明确且依赖编译通过 |
| 1 | 模拟三维输入与标准 Provider | XR Hands 适配模块、模拟场景 | 标准 API 可读、跟踪状态正确 |
| 2 | UVC 空间转换与关节映射 | 标定资料、三维转换、质量诊断 | 可先使用未标定预览参数；精度验收后续补做，估算能力已标明 |
| 3 | 真实输入、更新时序与恢复 | 真机 XR Hands 场景、生命周期实现 | 丢失/恢复可靠，无重复子系统或资源泄漏 |
| 4 | 标准 UI 与手势 | 食指圆圈、捏合 UI、官方 XR Hands 手势组件 | 标准按钮及手势事件正常，丢失时取消 |
| 5 | SDK 交付与新工程验收 | UPM 包、示例、导入文档、验证报告 | 全新工程可按文档构建并运行 |

阶段 1 与阶段 2 可分别推进；阶段 3 依赖二者的软件接口，按当前决定不等待实机标定精度验收。
缺少参数仅提示并使用开发预览默认值，标定工具和加载参数代码保留。阶段 4 可先用模拟输入开发，真实验收依赖阶段 3。

## 阶段 0：确定依赖与数据契约

**实现范围**

- 固定兼容 Unity 2022.3 的 XR Hands、Input System、XR Plug-in Management 版本；
  阶段 4 再固定 XRI 版本，Unity 6/其他引擎单列待验证，不能自动沿用结论。
- 设计独立 XR Hands 适配程序集或配套 UPM 包，明确缺少 XR Hands 时的条件编译和安装行为。
- 定义统一手部帧：序列号、来源时间/接收时间、左右手、根姿态、关节姿态、有效状态和估算来源。
- 约定米制、Unity 坐标轴、XR tracking origin、相机/物理头部/显示视图变换。
  当前镜片反射视图补偿不能未经推导就直接作为物理头姿用于手部空间定位。
- 确定支持关节与估算关节，位置/旋转/半径/速度等能力逐项声明，不支持的数据不伪造有效标记。
- 区分 SDK 自有手势类别与 XR Hands 关节 API；保留自有接口的兼容策略。

**交付**：依赖版本表、坐标变换说明、关节映射表、数据结构与能力约定、验收误差指标表。

**验证**：新建最小 Unity 工程编译通过；检查左右手/轴向/单位定义；确定空间位置、尺度、
角度、恢复时延及交互误触的目标值和测量方法。未确定的指标明确标记待定，不能据此宣告验收通过。

## 阶段 1：模拟手与 XR Hands Provider

**实现范围**

- 建立独立 `SpatialAI.XRHands` 适配模块，注册 descriptor，实现 Provider 和子系统。
- 实现 `GetHandLayout`、`TryUpdateHands` 及创建/启动/停止/销毁流程。
- 构造确定性的左右手三维输入，支持开掌、握拳、捏合、移动及失去跟踪。
- 规划动态更新和渲染前更新调用；输出更新成功标记、根姿态和关节状态。
- 使用标准 XR Hands 可视化验证 Provider，不依赖 UVC 或 MediaPipe 才能测试。

**交付**：Provider 源码、模拟输入源、可运行的标准手部显示场景、布局/状态/生命周期测试。

**验证**

1. 普通消费脚本通过 `SubsystemManager` 找到唯一、运行中的目标 `XRHandSubsystem`。
2. 左右手独立移动、旋转和消失；标准可视化方向和姿态符合模拟输入，骨长不随刚体运动变化。
3. 缺失关节、无效旋转和手丢失能通过标准状态被识别，不继续显示有效跟踪。
4. 编辑器 Play/Stop、场景往返后不重复注册/启动、不重复触发更新。
5. 对关节索引、单位、状态标记和左右手映射做确定性测试。

**边界**：此阶段只证明标准接口可用，不证明摄像头标定、单目深度或真实识别精度。

## 阶段 2：UVC 空间转换与标准关节映射

**实现范围**

- 标定实际 UVC 分辨率下的内参和畸变，记录裁剪、缩放、图像旋转/镜像处理。
- 获取相机到物理头部的安装外参，以及物理头部到 XR tracking origin/显示视图的关系。
- 选择并记录单目深度/尺度估算方案；评估 MediaPipe 世界关键点，
  不能直接将其局部米制结构当作手在相机前的绝对位置。
- 将 21 个点映射到 XR Hands 的标准 26 点布局；手掌和缺少的关节按方案估算或声明不支持。
- 推导关节朝向，处理左右手、遮挡、退化手型及置信度；提供估算来源与质量诊断。
- 转换到统一 tracking origin 空间，定义 3DoF 条件下的能力边界：头部平移未跟踪，
  不承诺房间尺度的真实世界固定手位置。

**交付**：标定数据及版本、坐标/骨架转换模块、误差测量工具、静态和动态对位报告。

**验证**

1. 合成输入验证投影/反投影、坐标轴、镜像及旋转组合，包含左/右手与退化输入。
2. 用已知距离和位置的标记，在多个距离、视野区域和手掌朝向测量位置/尺度误差。
3. 转头、抬头、侧倾及组合动作时检查手模型对位；通过镜片观察，截图不作为最终光学对位证据。
4. 遮挡或估算失败时降低有效状态，不将不可靠位置发布为精确跟踪。
5. 按阶段 0 的误差指标验收，输出误差分布及失败条件；无法达标则收窄能力范围或调整方案。

**边界**：单目估算版本可作为开发预览，但必须在 API/文档中说明精度，不据此宣称可靠近距离抓取。

## 阶段 3：真实数据、时序与恢复

**当前状态**：软件与独立工程检查已完成；APK 构建、安装与运行记录见 [阶段 3 文档](UNITY_XR_HANDS_STAGE3.md)。
单/双手显示、移出/返回及 USB 拔插后重新授权恢复已由用户确认；首次/重连授权优化、长时间与异常回退验收继续保留。

**实现范围**

- 将 Android 识别结果接入统一手部帧，再由 Provider 发布；避免多个组件各自打开同一摄像头。
- 主线程发布一致快照，动态更新/渲染前更新可复用最新帧；重复渲染不冒充新推理结果。
- 明确超时失效、手丢失、异常回退、左右手重新分配以及滤波参数。
- 处理手势开关、前后台、USB 重连、场景往返及应用退出；GPU 创建/调用/释放保持同线程。
- 记录输入吞吐、结果吞吐、结果年龄、丢帧、模型实际模式/delegate 和耗时分布。
  UVC 接收至结果可作为主机链路延迟，但不能标成传感器曝光至结果延迟。

**交付**：真实 XR Hands 场景、状态与生命周期逻辑、性能统计、异常恢复和长时间测试报告。

**验证**

1. 固定曝光/光照，预热后无手、单手静止/移动、双手各采样至少 60 秒。
2. 明确区分约 30 FPS 采集、约 22～24 FPS 识别及约 60 FPS 渲染，记录平均值/P50/P95。
3. 移出手、关闭识别和拔出 USB 后，在规定超时内失去标准跟踪；恢复后重新发布有效手。
4. 重复场景和前后台切换，检查重复消费者、GPU 错误及资源增长。
5. 长时间测试温升和性能下降，记录设备状态；测试 GPU 失败/分类失败的实际回退路径。
6. 若仍追求 30 FPS，再进行关键点/完整分类对照及模型 profiling，不能以降准确率代替验收。

## 阶段 4：XRI 标准交互

**当前状态**：可选包、动作资产、食指圆圈、骨架、方块/UI 示例和标准手势 prefab 已实现。取消可见射线及白球，保留标准方块交互；圆圈位置参照 `456.mp4` 的拇指/食指中点，样式保持不变，不随捏合锁定。方块/UI 跟随 XR 相机，手势状态合并到视野中部偏下、带背景且比方块更近的文字面板。
标准 UI/手势、丢失恢复与生命周期检查记录见 [阶段 4 文档](UNITY_XR_HANDS_STAGE4.md)。

**实现范围**

- 在已固定的 XRI 版本中提供所需 Input System 输入和姿态绑定，避免依赖特定 OpenXR 设备布局。
- 食指圆圈标记位置，以普通 Button.onClick 完成捏合松手点击，保留迟滞、去抖及恢复武装。
- 以 XRHandShape/XRHandPose 定义手势，原样使用 Unity Gestures 样例的 StaticHandGesture 事件；应用层不新增 Spatial 专有手势接口。
- 明确手部丢失/切换输入模式时取消交互，不保留被选中对象。
- 近距离 poke/抓取作为后续子阶段，只有阶段 2 的位置精度满足需求时才能宣告支持。
- MediaPipe 类别仅保留底层诊断，不作为应用手势事件来源。

**交付**：输入绑定、食指 UI 交互 prefab、标准形状资产与官方手势组件 prefab、接入说明及验收记录。

**验证**：左右手圆圈分别操作普通 UI；捏合松手只点击一次，标准手势开始/结束事件正常；
快速动作、边界抖动和双手同时操作不重复触发；跟踪丢失后无残留选择；
普通用户无需编写 MediaPipe/JNI 代码即可使用标准 XRI 组件。单列记录误触、漏触和恢复时延。

## 阶段 5：SDK 发布与用户新工程验收

用户已确认阶段 4 基础实机验收及阶段 5 基础 SDK 包安装接入验证通过；记录见 [阶段 5](UNITY_XR_HANDS_STAGE5.md)。

**当前状态**：版本化四包、安装与升级说明、示例及报告已交付本地预览目录；基础 SDK tgz 自动安装三个配套包，旧独立 installer 升级移除、重载、重试及搬迁验证通过。用户已确认消费工程 APK 手势场景正常，并确认最新合并包验证没有问题；早期两个隔离工程 APK 的安装受限记录保留为历史结果，不覆盖后续用户确认。精度、长时间和跨硬件验证继续独立列为待办。

**实现范围**

- 交付版本化 UPM 包或 SDK+XR Hands 配套包，明确依赖安装、XR 配置和支持设备。
- Android AAR 在源码 Git 中保持忽略，但进入发布制品，并与源码提交、模型、依赖校验值对应。
- 将必要的构建回调/项目配置整理到 SDK 的正式接入流程，用户不必从开发示例手动复制脚本。
- 提供模拟手、真实手可视化、XRI 交互三个可导入示例及故障排查说明。
- 保留显示/3DoF 独立使用方式，不强制每个内容项目启动相机和手势。

**交付**：UPM 发布包及校验清单、兼容矩阵、安装/升级说明、示例、全新项目验收报告。

**验证**：从空 Unity 2022.3 工程按文档导入包，配置 XR、构建并安装；
显示/3DoF 正常、标准 XR Hands 可读、XRI 示例可用；不依赖开发者本机绝对路径或未提供的构建目录。
缺少设备、权限或依赖时给出可理解状态。再验证纯显示项目与 SDK 升级场景。

## 完成定义与维护方式

- 每阶段交付保存源码版本、测试设备、配置、命令、指标及未通过项，更新
  [验证记录](VALIDATION.md)。未做的验证保持“待验证”，不因后续阶段开始而自动通过。
- 首个可交付里程碑是阶段 1：标准接口+模拟手；真实预览里程碑为阶段 3；
  用户标准交互里程碑为阶段 4；对外 SDK 交付完成需阶段 5。
- 目前不包括 6DoF 世界定位、Unity XR 手柄、iOS 手势、多机型保证或正式光学校准。
- 接口参考：[Provider API](https://docs.unity.cn/Packages/com.unity.xr.hands%401.2/api/UnityEngine.XR.Hands.ProviderImplementation.XRHandSubsystemProvider.html)、
  [XR Hands 数据模型](https://docs.unity.cn/Packages/com.unity.xr.hands%401.4/manual/hand-data/xr-hand-data-model.html)。
  引用用于理解接口，实施前以阶段 0 固定的包版本核对签名和行为。
