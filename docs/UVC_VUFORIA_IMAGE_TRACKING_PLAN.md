# UVC 共享与 Vuforia 图像跟踪实施记录

更新日期：2026-11-13
状态：规划中；以下待办均未实施或验收。以当前工作区代码为基线，实施时记录实际提交和构建版本，不以旧交接包版本为准。

## 目标与范围

Android 眼镜使用一台 UVC 摄像头，手势和 Vuforia Native 11.4.4 共享同一采集流。持续看到平面图像目标时，SDK 持续输出目标相对头部的位姿，Unity 在该目标的局部位置显示物体。佩戴者靠近、远离或绕图像小范围移动时，物体随相对位姿呈现相应的透视变化。

不依赖 Vuforia Unity 插件、ARCamera 或世界重定位；本期不提供房间级 6DOF、遮挡后世界锁定或精度承诺。图像丢失、设备断开或位姿过期时隐藏物体；重新直接跟踪后恢复。目标实际效果在功能完成后真机验证。

## 当前基础与缺口

- `SpatialAIAndroid/runtime/platform/android/hands/UvcCapture.java` 将 UVC NV21 帧送到 `CameraService`。`CameraService` 对消费者提供 I420，支持多订阅、每消费者独立线程、保留最新待处理帧和引用计数；UVC 时间戳为主机接收时间。
- `SpatialHandBridge` 当前创建并关闭相机服务及 UVC 采集，故尚不能独立于手势提供共享相机；需调整所有权和生命周期，保留现有手势行为。
- Unity SDK 已有 Android 桥接和 VISOR-X 双目显示能力。当前源码检索未发现可直接复用的 Vuforia 跟踪实现；交接文档中的 Android/Web 结果仅作参考，Unity 路线尚未验收。
- 当前 SDK 文档记录 Android ARM64、IL2CPP、GLES3、横屏；具体 Unity、Android、手机和眼镜版本按每次构建与测试记录。既有头部追踪为 3DOF。

## 架构与约定

```text
UVC → 共享采集服务 → I420 帧订阅 ┬→ 手势
                               └→ 格式适配 → Vuforia Native Driver → Image Target Observer
                                                                        ↓
Unity SDK ← 原生跟踪桥接 ← 状态、时间戳、目标版本、位姿 ← Vuforia observation
    ↓
头部局部目标锚点 → 虚拟物体 → 现有 VISOR-X 双目相机
```

由共享服务唯一持有 USB 设备与采集实例，消费者各自订阅和释放；最后一个消费者退出后关闭采集。服务显式报告权限、等待设备、运行、断开和错误，恢复策略需避免重复打开。相机参数冲突需明确拒绝或协商，不能静默更改另一消费者的配置。暂停、拔插、重连及关闭的所有权和异步回调顺序需有测试。

Vuforia 用自定义 C/C++ Driver 接收外部帧和匹配输入模式的相机内参。实施时以 11.4.4 SDK 的 Driver 头文件核实支持的格式、stride、帧时间、缓冲区所有权与线程约束，不假设可直接使用 I420；必要时转换并测量开销。原生引擎和 Unity 各只有一个明确的生命周期所有者。

输出契约需明确源矩阵方向、存储顺序、坐标轴及单位；桥接转换为 Unity 头部局部坐标、米和 Unity Quaternion，使用相机到头部外参。目标姿态与 XR 相机层级只应用一次头部变换，避免将相机跟踪位姿和头部旋转重复叠加。约定目标局部原点、平面法向和物体偏移，并用已知矩阵测试正对、90°及倾斜。实际内参、外参、畸变和左右眼光学贴合仍需真机验证。

## 阶段与待办

- [ ] 确认当前 Android/Unity 工程、构建链、目标设备和工作区基线；记录 commit、未提交变更和产物摘要。
- [ ] 准备官方 Vuforia Native 11.4.4 Android SDK、Driver 头文件及有效应用许可证；核对授权、再分发条件、ABI、依赖和版本兼容。许可证不提交仓库或写入日志；确定本地及构建注入方式。
- [ ] 准备实际 UVC 模式对应的相机内参、畸变参数与相机到头部外参；无可用标定时明确标记为待验证，不把默认值当作精确标定。
- [ ] 确认首个测试目标图片、实际印刷宽度、目标局部原点和物体偏移；测试图与纸卡裁切、方向及比例一致。

完成条件：依赖和配置来源可复现，缺失项和限制有记录。

### 1. UVC 共享服务

- [ ] 从手势桥接中分离相机及 UVC 采集所有权，提供可独立使用的共享服务；手势改为订阅者，预览能力保持可用。
- [ ] 定义获取、订阅、取消、最后释放的线程安全契约，定义采集参数冲突、USB 权限、失败和恢复行为。
- [ ] 保留有界缓冲、最新帧优先及引用计数；明确 I420 平面布局、尺寸、方向、镜像、stride、序号和时间戳含义。
- [ ] 增加必要诊断：设备和实际模式、订阅者、采集 FPS、消费者丢帧、错误及帧龄；不得阻塞采集线程。
- [ ] 验证仅手势、仅测试消费者、两消费者、消费者独立启停及最后释放；覆盖权限拒绝、暂停恢复、USB 拔插、重复启动/停止和手势回归。记录实际 USB 打开次数，确认同时运行只打开一次。

完成条件：两消费者接收同一采集流，互不关闭对方，停止后资源释放，原有手势功能无明显回归。

### 2. Vuforia Native 跟踪

- [ ] 在 Android 模块集成官方 Native 库及自定义 Driver，控制 Engine、Driver、Observer 创建、启动、停止和销毁顺序；不引入 Unity 插件或第二个相机采集器。
- [ ] 实现共享帧到 Driver 的格式/方向/时间适配、内参传递和安全缓冲生命周期；忙时丢弃过期帧，不形成无界积压。
- [ ] 从本地图片和实测宽度创建 Image Target Observer；输出目标 ID、版本、跟踪状态、位姿、序号、时间戳及错误。先实现单目标；网站下载及换图不是首轮阻塞项，如需要再接入并校验资源。
- [ ] 目标切换或重建时清除旧观测；确认直接跟踪、扩展/推断、丢失等状态的实际 Native 映射，不把创建成功视为识别成功。
- [ ] 完成 Android 构建、加载、权限和生命周期检查；用实际 UVC 和目标验证至少一次直接识别及连续位姿输出。记录模式、目标摘要和日志；真实效果质量留至最终验收。

完成条件：不依赖 Unity 插件，原生层能使用共享 UVC 对已知目标输出连续状态与位姿，并能干净停止与恢复。

### 3. Unity SDK 与场景

- [ ] 增加面向应用的图像跟踪接口：配置目标、启动、停止、状态/错误、最新样本和状态变化；明确线程、对象所有权、时间戳时钟域及样本有效期。缺少设备或许可证时返回明确错误。
- [ ] 样本至少包含目标 ID/版本、物理宽度、状态、序号、采集/接收时间与头部局部位置和旋转；原生状态保留足够信息以区分直接跟踪及其他状态。
- [ ] 在 Unity 主线程更新目标锚点，物体挂在锚点下；仅直接跟踪且样本未过期时显示。暂停、断连、切换目标及销毁时清除或隐藏旧内容。
- [ ] 提供最小示例场景及安装、配置和调用说明，使用现有 VISOR-X 双目相机；示例展示可配置目标图、宽度及物体局部偏移。
- [ ] 验证目标相对头部的矩阵转换、轴向、米制尺度和过期处理；构建 Android APK，验证仅识图以及识图加手势。

完成条件：应用开发者通过 SDK 接口和示例场景即可显示跟随目标的物体；不要求自行接触 Vuforia 原生 API。

### 4. 真机效果验收

- [ ] 使用细节丰富的对照图，再使用实际蓝卡；记录图案摘要、实测宽度、距离、角度、光照和设备/软件版本。
- [ ] 静止、靠近、远离、左右移动及倾斜时记录锁定、丢失、恢复、可用距离和物体相对卡片表现；开始移动时须已锁定。卡片超出视野或被遮挡时检查隐藏与恢复。
- [ ] 佩戴观察左右眼的物体位置和合像；屏幕截图只证明绘制，不作为真实光学贴合证据。
- [ ] 分别测试仅识图及识图加手势，记录 UVC 实收 FPS、位姿更新率、Unity FPS、丢帧、帧龄 P95 和运行时错误。当前主机接收时间不能代表曝光时间或端到端延迟，端到端测试须另注明方法。
- [ ] 记录结果与未解决问题；识别质量和数值阈值在真实设备结果可用后确定，不将“能够构建”作为效果通过。
